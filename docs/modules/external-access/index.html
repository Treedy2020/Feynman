外部权限，一个内核，五个 Provider。

External Access 是 Feynman Server 内部的独立模块。统一管理账号 Connection、项目绑定、权限申请和调用校验；Provider 保留原生 CLI，不重写 SDK。账号缓存留在 Server，Agent 通过固定 MCP 获取结果；受控 Git clone 单独处理短暂的沙盒凭证使用。

已实现

登录、项目绑定、业务 Grant，分别管理。

Connection

所有者登记、CLI 验证的外部账号。公开 ID、身份、实例，不公开 Token 或私有路径。

ProjectCliBinding

指定项目 / Provider / 账号 / 到期时间；GitLab 与 Git 还绑定 namespace/repository。默认 24 小时，可设 60 秒至 7 天。

Tool Grant

沿用 Tenant / Project / Tool 业务许可。认证与绑定不自动授予业务权限；实际读取前重新验证。

每项目每 Provider 只绑定一个账号 / 仓库。同一所有者可显式复用 Connection，A 登录不使 B 获权。细粒度资源 ACL 与分支策略仍待完善；使用租约已接入指定 workload，不代表 Provider 凭证到期。

已实现 · 非预留项

保留每种 CLI 的真实认证机制。

DWS / dws ↗

device 认证缓存提升为 Connection；企业搜索使用指定账号，不回退主机 profile。

GitLab / glab ↗

所有者显式导入原生登录或 Token stdin；固定仓库元数据与开放 MR 读取。

Git / git ↗

委托 GitLab HTTPS Connection；固定 remote 读取和 Sandbox clone，不提供 push。

Slate / dip-slate ↗

真实浏览器 PKCE 或指定 Keychain profile 导入；身份、个人任务和可见项目只读。

Drlee / drlee ↗

原生浏览器或单账号缓存导入；独立刷新，消息读取需所有者绑定渠道 UUID。

统一流程

Agent 申请，所有者认证、绑定和批准。

账号认证、Project Binding 和业务 Tool Grant 分别完成；每次调用核对实际身份、到期、停用和最新绑定。请求不自动登录或获权，配置状态也不证明账号仍有效。

完整的共同规则、设备协议、公开状态与撤销边界见 公共认证与授权流程；各 CLI 的具体认证方法、命令与限制保留在子模块。Slate / Drlee 新登录由所有者 CLI 等待，不冒充 DWS 的异步 device 状态机。

初版已接入 八类组合策略，不扩张为巨型 Provider 基类。项目 env 注入、事实源订阅和长期记忆各有独立职责。事实来源历史、Schedule / Inbox 已实现；env 装载、使用租约和通用 MemoryStore也已接入，分别复核用户批准与证据权限。Drlee 的持久 ObservationSource / listener 尚未接入，本版仅固定 MCP 读取。

可运行 CLI / HTTP

管理凭证的入口，不暴露给 Agent。

feynman access providers
feynman access connections list
feynman access status PROJECT_ID
feynman access request PROJECT_ID --provider gitlab \
  --capability gitlab.repo.read --reason "读取仓库"
# 所有者登记 Connection 后：
feynman access bind PROJECT_ID --provider gitlab \
  --connection CONNECTION_ID --repository team/repo
feynman external-tools grant PROJECT_ID gitlab.repo.read
feynman external-tools invoke PROJECT_ID gitlab.repo.read --arguments '{}'
feynman access unbind PROJECT_ID --provider gitlab
feynman access connections disable CONNECTION_ID

新增 HTTP：/v1/access/providers、/v1/access/connections 及项目 /access、/access/requests、/access/bindings、/access/invoke/{tool}。所有者管理接口不注册为 MCP；新接口拒绝 Origin 请求并设置 no-store。详细认证命令见子模块。

边界与验收

可信个人 MVP，不是通用 Vault。

~/.feynman/private/external-access/ 保存私有 SQLite、0600 Token 和单账号原生缓存，目录 0700；不是加密保险库。DWS 使用 private/dws/ 缓存。请安全备份私有目录，不放入仓库或项目卷。

观察 CLI 在 Server 执行。Agent 不提供 binary、任意 argv / env、主机路径或 Token。固定 native 读取只接受空对象；clone 仅接受 UUID idempotency_key，目标来自用户绑定。Git Token 短暂进入容器固定进程环境，不写配置或 Workspace；容器 root Agent 能观察该进程，不是对恶意 Agent 的秘密隔离。后续认证 fetch / push、SSH、merge / pipeline 不在当前能力中。

仅 loopback、固定 local-user；管理与项目 MCP 是协议边界，不是同一 OS 用户间的强隔离。能读私有文件的进程仍可绕过，不可开放给不可信租户。

离线验收覆盖跨项目拒绝、缺失 Grant / Binding、撤销、到期、身份变化、秘密脱敏、参数逃逸、私有文件模式、MCP 禁止登记密钥、原生 askpass 与 DWS 绑定搜索。原生 Provider 测试追加独立账号刷新与只读命令约束。
