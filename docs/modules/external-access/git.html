Rust 初版 · Sandbox clone 已接入

Git：授权远端，不发明登录。

绑定一个 GitLab HTTPS Connection，读取指定仓库 refs，或将该仓库拉进 Sandbox。Agent 可在工作树开发与测试；没有默认推送、部署权限。

Transport binding

本地代码操作与远端认证是两回事。

Git 没有通用 git login。HTTPS credential / askpass 与 SSH 身份是不同机制；当前只支持 GitLab HTTPS，不读取个人 helper、导入 SSH 私钥或转发 SSH agent。见 Git 官方凭证机制。

GitLab API Grant 不隐含 Git 读取 Grant。绑定同一账号仍需分别批准 git.remote.read；Token 实际仓库权限是上限。

# 先登记 GitLab Connection，见 GitLab 子模块
feynman access bind PROJECT_ID --provider git \
  --connection CONNECTION_ID --repository team/repo
feynman external-tools grant PROJECT_ID git.remote.read
feynman external-tools invoke PROJECT_ID git.remote.read --arguments '{}'
feynman access unbind PROJECT_ID --provider git
Fixed native Git

host 来自账号，repo 来自用户绑定。

固定目标 https://HOST/NAMESPACE/REPOSITORY.git。git.remote.read / git_remote_read 接受 {}，在控制面执行 ls-remote；git.workspace.clone / git_workspace_clone 接受 UUID idempotency_key，在已运行且所有权校验通过的 OpenSandbox 容器内拉到 /workspace/repo。没有本机 clone fallback，不接受任意 remote、目标路径或 argv。

feynman external-tools grant PROJECT_ID git.workspace.clone
feynman external-tools invoke PROJECT_ID git.workspace.clone \
  --arguments '{"idempotency_key":"4a7f8608-a2f4-45c8-90d3-a29cf35a19c9"}'

每个新 clone 使用新的 UUID；未知结果保留同一 UUID 并先检查 Workspace。成功后同一 key + remote 返回 already_completed；已有 repo 或不同 key 会拒绝。失败留下部分工作树以便检查，不自动删除重试。收据不是强抗篡改凭证；Workspace 是可信 Agent 可写环境。

禁用系统 / 全局 Git 配置、默认 helper、终端提示、HTTP 重定向、模板和 hooks，仅允许 HTTPS。先 no-checkout，再固定 checkout HEAD；不执行 submodule、LFS、依赖安装、迁移或项目脚本。Token 经受控 stdin 进入固定 Git 进程环境，askpass 校验目标 host / port / repo；不会写到 remote URL、argv、Git 配置、Docker 配置或收据。见 Git 配置文档。

边界与验收

写代码不等于批准发布。

clone 后 Agent 通过原生 Executor 编辑工作树、编写与运行测试。未开放通用 fetch、push、force、delete、tag 写、SSH 或部署；GitLab API 的 MR 写入也独立预留。撤销新调用权限不删除已拉取的代码；正在进行的操作和已产生的结果不能承诺回滚。

Sandbox root Agent 可观察临时 Git 进程环境，不能声称 Provider 凭证对恶意 Agent 保密。这是可信个人开发 MVP，不是不可信租户隔离。HTTP Token 可能具有更广的 Provider 权限，固定操作策略不是 Token 权限缩减；生产应使用窄权限凭证。
