初版已实现 · Drlee 0.0.1

Drlee：独立账号缓存，原生刷新。

保留 Drlee 原生认证语义。Feynman 复制一个选定账号的 Token Pair 到专用 DRLEE_HOME，Agent 获得受许可的观测结果。

Owner native login/import

不挂载整份个人认证目录。

feynman access connections import-drlee --hostname drlee.dip-aitech.com
# 可选 --source-home /path/to/private/drlee --handle ACCOUNT_HANDLE
# 或启动新的原生浏览器授权：
feynman access connections login-drlee --hostname drlee.dip-aitech.com

默认显式导入 DRLEE_HOME 或 ~/.drlee/accounts.json 中选定的 active account；验证文件为私有常规文件、账户版本为 1、唯一 handle 与 endpoint 一致。仅选中账号进入 Broker，不复制其他账号。新登录使用临时私有目录运行原生 drlee auth login，成功后交给 Broker 登记。

Broker 的 drlee auth 在线核对 verified、email、endpoint 与绑定身份；原生 CLI 刷新后只写 Feynman 私有缓存，不修改个人原始文件。公开 DTO 不包含 access / refresh Token、缓存路径或 credential。原生 CLI 的 JSON 输出再次清除密钥字段和实际秘密字符串。

Separate business grants

消息频道由用户绑定，Agent 不自选。

feynman access bind PROJECT_ID --provider drlee --connection CONNECTION_ID
feynman external-tools grant PROJECT_ID drlee.identity.read
feynman external-tools grant PROJECT_ID drlee.channels.read
# 要读某频道消息，用户重新绑定同一账号并指定频道 UUID：
feynman access bind PROJECT_ID --provider drlee --connection CONNECTION_ID --resource-id CHANNEL_UUID
feynman external-tools grant PROJECT_ID drlee.messages.read
feynman external-tools invoke PROJECT_ID drlee.messages.read --arguments '{}'

工具：drlee.identity.read、drlee.channels.read、drlee.messages.read（绑定频道，20 条）、drlee.knowledge.read（个人空间元数据）。MCP 对应 drlee_identity_read / drlee_channels_read / drlee_messages_read / drlee_knowledge_read。均为固定只读命令，业务参数为 {}。channels Grant 授权可见频道列表，messages Grant 单独允许一个绑定频道；不提供发消息、建任务、邮件发送或任意 RPC。

Private state and recovery

访问可停用，已经读到的事实不能收回。

缓存位于 private/external-access/CONNECTION_ID/accounts.json，目录 0700、文件 0600；包含 refresh Token，必须安全备份。设置 FEYNMAN_DRLEE_BIN 为可信已安装的本机二进制。只有 macOS binary 也能通过控制面代理使用，不要求复制到 Linux 镜像。

身份改变、账号停用、解绑、Grant 撤销或到期会拒绝新调用；停用不是 Provider Token 吊销。导入出的两份原生刷新缓存可能受 Provider refresh rotation 策略影响，若出现失效应对 Feynman 单独 login-drlee，不保证两份会话永远并行有效。

这是可信个人 MVP，不抵御同一主机用户读取凭证。未来 RSS/被动事件订阅还需 Source Adapter；本轮实现认证与 MCP 受限读取，不声称已经有 Drlee 后台消息监听。共同流程见 公共认证流程。
