DWS：设备登录与项目事实源。

Device 是设备登录：Server 上的 dws 发起认证，用户打开钉钉验证页面确认，CLI 等待结果。Feynman 托管等待过程和私有缓存，再验证账号；不让 Agent 接收 Token，也不把登录等同于搜索获权。

设备登录CLI 操作状态与排查MCP / HTTP搜索与存储取消与恢复验证记录
DWS 专属实现

用户在浏览器确认，Server 在后台等待。

允许发起认证

所有者授予项目 dws.auth.device。Agent 只能提交理由，不能选择账号密钥、登录地址或任意参数。

启动原生 CLI

Server 创建独立认证目录，运行固定设备登录命令。HTTP 立即返回申请，不阻塞等用户。

用户确认

展示真实验证链接、用户码和截止时间。用户在钉钉页面登录并确认授权；Agent 不代替同意。

验证实际身份

dws 完成并保存缓存后，Server 重新检查有效性与企业 / 用户身份，成功才标记 authorized。

# Server 内部固定执行，不是交给 Agent 的任意命令入口
dws auth login --device --no-browser --format json
# 完成后重新检查；后续检查显式使用已记录的账号 profile
dws auth status --format json

设备协议的轮询由 dws 负责，Feynman 不重写 OAuth 客户端。CLI、项目 MCP 或未来前端读取的是 Feynman 公开进度。关闭 MCP 或结束 Agent Turn，不会销毁 Server 托管的任务。

通用概念、设备协议、公开字段与敏感字段、项目授权和凭证边界已抽到 公共认证与授权流程。本页只规定 DWS 的命令、状态和限制。

所有者与 Agent 的操作入口

先登录，再登记、绑定和批准搜索。

# 1. 所有者允许项目发起 device 登录
feynman external-tools grant PROJECT_ID dws.auth.device
# 2. 请求返回 AUTHORIZATION_ID；打开显示的链接完成钉钉确认
feynman dws-auth request PROJECT_ID --reason "读取项目事实" --wait
# --wait 只观察进度，不替用户确认；另一个终端可继续查询
feynman dws-auth list PROJECT_ID
feynman dws-auth status PROJECT_ID AUTHORIZATION_ID --wait
feynman dws-auth check PROJECT_ID AUTHORIZATION_ID
# 3. 确认为 authorized 后，登记经过验证的账号
feynman access connections register-dws PROJECT_ID AUTHORIZATION_ID
# 4. 所有者绑定该项目，再单独批准业务读取
feynman access bind PROJECT_ID --provider dws --connection CONNECTION_ID
feynman external-tools grant PROJECT_ID dws.aisearch.enterprise
feynman external-tools invoke PROJECT_ID dws.aisearch.enterprise \
  --arguments '{"queries":"项目事实","types":["document"]}'

登记时再次验证账号，Connection 身份为 corp_id:user_id。绑定默认有效 24 小时；同一账号给第二个项目使用，仍需分别绑定和授权。原有主机默认 profile 不会自动迁移或作为搜索回退。

# 分别处理未完成的登录、业务 Grant、项目绑定或整个账号
feynman dws-auth cancel PROJECT_ID AUTHORIZATION_ID
feynman external-tools revoke PROJECT_ID dws.aisearch.enterprise
feynman access unbind PROJECT_ID --provider dws
feynman access connections disable CONNECTION_ID

取消登录不吊销已发出的 Token；解绑不删除账号。公共参考中的 撤销边界 解释这些动作的差别。

DWS 认证状态 · 不是通用 Grant 状态

拿到链接，不代表已经登录。

API 状态中文含义用户 / 客户端下一步
preparing正在启动认证进程。继续观察公开进度。
waiting_for_user等待用户在钉钉确认。打开验证链接，核对用户码和实际权限后同意或拒绝。
authorized已完成登录并验证身份。所有者可登记 Connection；尚未自动获得搜索权。
authentication_required重新检查后发现未认证。重新发起登录并显式登记 / 绑定，不回退其他账号。
expired等待超过设备码期限。需要时重新申请；旧链接不能当作仍有效。
denied外部授权被拒绝。停止等待，不绕过拒绝。
cancelled用户取消或发起认证权限被撤销。只表示本次流程结束，不证明 Token 已吊销。
failed启动、输出、外部认证或身份校验失败。查看公开错误码；不返回原始 CLI stderr。
interruptedServer 重启前有未完成流程。确认需要后重新申请；不会自动重建旧 OAuth 进程。

status / GET 查看已保存记录；check 执行新鲜检查，必要时由 dws 刷新认证。短暂检查异常返回错误，不伪造一次成功。身份与原记录不符时拒绝。checked_at 表示真实检查完成时间，不是 Session Heartbeat。

Provider 专属 MCP / HTTP

展示链接和进度，不展示密钥。

MCP feynman_dws_authorization 支持 request / list / status / cancel / check，需项目 dws.auth.device Grant；它不是只读工具，因为登录会改变账号状态。request 只接收短理由，后续操作使用授权 ID。项目与身份由 Server 上下文注入，不由模型指定。

它不同于通用 feynman_access：后者只查询 Provider / 项目状态、登记能力需求，不启动 DWS 登录，也不能批准、绑定或录入凭证。

原生 Codex 只对 Feynman 管理的这一个受限 MCP Server 配置 default_tools_approval_mode=approve，避免已由 owner 明确授予的项目工具被重复原生确认拒绝；每次真实调用仍由 Broker 检查 Grant、绑定和范围，未获权即拒绝。不是全局关闭 Shell 审批，也不替用户同意 DWS 浏览器认证。

HTTP含义
POST /v1/projects/{project}/dws-authorizations输入 {"reason":"读取项目事实"}，返回 202 与公开记录。
GET /v1/projects/{project}/dws-authorizations列出当前用户在该项目的申请。
GET /v1/projects/{project}/dws-authorizations/{id}读取进度与公开验证信息；不触发新登录。
DELETE /v1/projects/{project}/dws-authorizations/{id}取消未完成的流程。
POST /v1/projects/{project}/dws-authorizations/{id}/check输入 {}，重新检查 / 按需刷新，不只是读历史状态。

等待时可每秒读取 GET：展示 verification_uri_complete，无此字段则使用 verification_uri；同时显示 user_code 与 expires_at。只接受适配器验证过的 HTTPS 钉钉域名。完成或中止后清除挑战字段；不要依赖旧链接。

响应设置 Cache-Control: no-store 与 Referrer-Policy: no-referrer。device_code、OAuth 授权码、Token 和私有路径不是公开字段。申请响应明确报告 credential_location: local-control-plane、sandbox_installed: false。

搜索与私有缓存

固定企业搜索，用明确的账号。

业务读取执行固定 dws aisearch enterprise，只接受经过类型校验的关键词、内容类型和时间范围。Broker 核对项目 Grant、绑定有效期、Connection 停用与实际身份；读取前再次检查最新绑定。返回结果时递归移除常见认证字段，但不保证业务消息正文或附件没有敏感内容；应最小化来源范围，评估输入另做脱敏和凭据审计。

请求缓存位于 ~/.feynman/private/dws/<authorization-id>/。每次请求独立设置 DWS_CONFIG_DIR 和 DWS_KEYCHAIN_DIR，使用 DWS_DISABLE_KEYCHAIN=1 的本地私有文件存储；清除继承的 DWS 配置与 app secret，仅保留运营者网络设置。目录 0700，不迁移个人 profile 或系统 Keychain。

Connection、绑定、申请与最小审计保存于 private/external-access/。凭证不进入项目卷或镜像；这不是加密 Vault、临时凭证租约或不可信多租户隔离。固定关键词与只读标记也不能保证限制到某个群或文档集合。

当前企业搜索只发现内容，不自动读取命中资源或开放更多 dws 写操作。Server 不回退主机 profile；独立遗留适配器的兼容开关不是默认授权路径。

指定消息源的独立只读能力

dws.chat.messages.read / MCP dws_read_messages 需要独立 Grant，以及 owner 配置的 DwsScope：目标类型 / 稳定 ID 列表、start、end。Agent 只能选择其中一个目标和范围内子窗口，不能自己扩大 Scope；命令固定为 dws chat +chat-messages，分页至明确上限，显式指定已验证 profile。结果的 complete / hasMore / failures 必须检查，不把截断结果说成完整历史。

feynman access dws-scope PROJECT_ID --scope-json '{"targets":[{"kind":"group","id":"STABLE_GROUP_ID"}],"start":"2026-09-01T00:00:00+08:00","end":"2026-09-02T00:00:00+08:00"}'
feynman external-tools grant PROJECT_ID dws.chat.messages.read

Owner HTTP：PUT /v1/projects/{project}/access/dws-scope。这不会创建业务 Grant；其他工具如企业搜索不受此消息 Scope 限制。附件下载、发消息与原始 CLI 凭据装载均未开放。见 初版验证记录。

DWS 生命周期限制

持久化进度，不假称恢复进程。

  • 公开元数据存入 SQLite，按 Tenant / Project / 请求用户隔离；同项目有效等待请求去重，状态更新避免登录完成覆盖取消。
  • 最多 16 个活动认证任务，等待上限 600 秒，并受实际设备码截止时间约束。运行中持续重查发起认证的 Grant。
  • 认证检查与绑定搜索共享刷新锁，避免同一缓存并发刷新；目前 DWS 使用较保守的串行检查。
  • 取消或正常关闭 Server 会中止托管任务，子进程采用 kill_on_drop。突然 OS 崩溃 / SIGKILL 不承诺即时杀死子进程，设备码期限仍限制等待。
  • 重启把未完成请求置为 interrupted 并清除挑战。成功缓存与 Connection 可持久化，恢复后的业务调用仍需验证。

dws 目前把人类可读设备提示写入 stderr、最终 JSON 写入 stdout。适配器固定提示语言、去除 ANSI，只提取验证链接、用户码和期限；输出有界，不记录原始文本。CLI 提示格式变化可能需要更新适配器，不声称这是稳定的结构化进度协议。

本实现没有永久刷新 daemon，也不因登录成功自动唤醒 Agent。授权缓存被另一项目显式复用后，各项目业务 Grant 独立；撤销原项目发起登录的权限，不连带撤销另一项目已批准的搜索。

验收与历史边界

离线成功，不等于真实用户已同意。

离线测试运行真实 Rust HTTP / MCP / CLI，仅替换外部 dws 进程。覆盖拒绝、链接展示、去重、身份验证、取消、过期、秘密脱敏、账号变化与重启；接入测试还覆盖认证缓存 → Connection → Binding → 企业搜索及共享账号的独立权限。

cargo build --workspace
python3 -m unittest discover -s scripts/smoke -p test_dws_authorization.py -v
python3 -m unittest discover -s scripts/smoke -p test_external_access.py -v
