Rust 初版 · 原生登录导入

GitLab：账号与仓库协作分开。

原生 glab，所有者 Token stdin 或显式导入本机登录；指定仓库与开放 MR 读取。未开放评论、创建 MR、合并和流水线。

Explicit owner import

已登录 glab，可以由所有者复用。

feynman access connections import-gitlab --hostname gitlab.star-x.dev

所有者 CLI 从选定 glab 实例的原生配置 / Keychain 读取凭证，私有 stdout 管道交给 Broker；重新执行 glab api user 核对身份后创建 Connection。不打印 Token，不覆盖或挂载个人配置。认证后仍需逐项目 Binding 和业务 Grant；Git 沙盒拉仓库另行批准 git.workspace.clone。2026-10-09 已验证用户公司实例身份和指定 Slate 仓库。

Owner token stdin

显式输入或导入，不把密钥写入聊天。

显式实例 DNS hostname，不接受 scheme / port / userinfo。Token 从有界 stdin 读至 EOF，经可信 loopback 交给 Server；glab api user 验证成功才创建 Connection。不要 echo 真 Token 到历史，使用可信密码管理器安全管道；此命令不是隐藏输入交互。

只读 API 通常需要 read_api；若同一账号用于 Git HTTPS 读取，还需 read_repository。验证身份不保证某仓库可访问，真实 Provider 权限仍是上限。见 GitLab Token 权限。

glab 原生支持 device 登录，但 Feynman GitLab V1 尚未托管该流程。见 glab 认证文档。

# 凭证从可信管道传入 stdin，不放在 argv / 聊天中
feynman access connections register-gitlab \
  --hostname gitlab.example.com --token-stdin
feynman access bind PROJECT_ID --provider gitlab \
  --connection CONNECTION_ID --repository team/repo
feynman external-tools grant PROJECT_ID gitlab.repo.read
feynman external-tools grant PROJECT_ID gitlab.mr.read
feynman external-tools invoke PROJECT_ID gitlab.repo.read --arguments '{}'
feynman external-tools invoke PROJECT_ID gitlab.mr.read --arguments '{}'
固定 API GET

两个读操作，不代理任意 endpoint。

能力 / MCP行为
gitlab.repo.read / gitlab_repository_read读取绑定仓库元数据，输出字段 allowlist。
gitlab.mr.read / gitlab_merge_requests_read读取绑定仓库一页开放 MR，最多 50；无分页 / diff / 写操作。

只接受 {} 参数，仓库由所有者 Binding 确定。每次使用同一 Token 验证实际身份，执行前再次核对 Grant、停用、到期与绑定。原生 API 机制见 glab api。

安全边界

私有缓存，不是强隔离 Vault。

CLI 清洁环境，显式 GITLAB_TOKEN、私有 GLAB_CONFIG_DIR 与固定 GET；不继承个人认证变量。原始 stderr 不返回，输出有界、超时、已知 Token 字符串脱敏。Token 是 0600 私有明文文件，子进程环境可被同一 OS 用户观察。

停用 Connection 只阻止本地新调用，不远端 revoke Token；需在 GitLab 自行吊销。离线测试覆盖跨项目、账号变化、撤销、脱敏与参数逃逸；2026-10-09 已显式导入公司的原生 glab 登录，真实 Agent 读取 Slate 仓库元数据并完成沙盒 clone。共同规则见 公共认证与授权流程。
