发现的 Feynman 缺陷：任务完成后，Agent 无法读取日志。

同一项目、Agent、有效租约与相同 workload：用户 CLI 日志读取成功，正确参数 {"id":"work_..."} 的 Agent stdio MCP 请求稳定被拒。只读对照未启动新任务、未重新调用模型。租约当时仍有效，任务已完成，排除了到期和缺失日志。

根因在 crates/feynman-server/src/resources/environment.rs：workload.logs 调用 check_lease，后者要求 state == active；后台对账将结束任务设为 completed 后，Agent 读日志也被拒。Owner 路径不经过这项检查。MCP 又把上游非 2xx 折叠成通用拒绝，Agent 不能辨明原因。

建议将“继续执行/续租许可”和“读取本 Agent 已结束任务的日志许可”拆开，保留项目、身份、审批 revision、有效期、撤权和实例校验；不要简单移除授权检查。本轮只诊断并留证，未修改后端权限行为。Agent 读取了自身探针结果文件完成分析，原失败记录保留。
