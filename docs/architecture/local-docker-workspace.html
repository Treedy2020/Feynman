Local-first · Docker Desktop · 2026-10-09

在本机测试，同样保留沙盒 Workspace。

Rust Server、Codex 会话和授权记录留在本机，执行通过原生 Executor 进入本机 OpenSandbox 容器。每个 Project 使用独立的持久 Docker 卷；不经过 SSH 或 Tailscale，不自动迁移远程数据。

注意区分：--provider local 是宿主机目录，不是容器沙盒。本机容器仍用 --provider opensandbox，只是可信 Operator 配置中的 executor_ssh_target 为 null，API 与 Executor 均只通过 loopback 访问。

运行方式启动运行时版本测试持久化安全与限制

会话在本机，命令与文件在 Linux 容器。

CLI / 本地 Harness
    │
    └─ Rust Server · 127.0.0.1:4318
       ├─ SQLite / Codex Home / 外部认证 / 来源历史
       ├─ Codex App Server ── loopback WebSocket ── 原生 Executor
       └─ OpenSandbox API · 127.0.0.1:18081             │
                                                     └─ Linux 容器 /workspace
                                                        └─ Project 独立持久卷

复用现有 OpenSandbox Adapter，不新增 Docker Provider 或另一套 Agent 状态模型。应用环境与租约使用相同的身份／卷校验脚本，通过本机 Docker exec 的 stdin 交付；远程仍使用 SSH，SSH 失败不会改走本机或宿主机运行。

独立配置，保留现有远程项目。

需要运行中的 Docker Desktop、Rust、uv、npm 和可用的 Codex binary。首次准备下载固定版本 OpenSandbox 0.2.3、execd v1.0.22，以及与本机 Codex 对齐的 Linux binary；校验 npm dist integrity，再构建不含凭据的执行镜像。

cd /absolute/path/Feynman
cargo build --workspace

# 明确导入已经配置好的公司 Feynman Codex Home；不读个人 profile
python3 scripts/opensandbox/local.py prepare \
  --import-codex-home /absolute/company-feynman-codex-home
python3 scripts/opensandbox/local.py up
python3 scripts/opensandbox/local.py status
python3 scripts/opensandbox/local.py cli -- auth status

默认测试 Home 为 $HOME/.feynman-local-sandbox，与现有 $HOME/.feynman 分开。使用全局 --home /absolute/dedicated-home 可另选目录；prepare 的 --server-port / --sandbox-port 只用于首次配置，已有配置不同会拒绝覆盖。公司模型配置与 file auth 显式复制到测试 Home 的 codex/；已有不同 auth 不覆盖，不迁移 Session。

运行时独立保存，不依赖 Homebrew 的旧版本目录。

本机 Codex 与 Linux Executor 必须保持明确的版本绑定。首次 prepare 将宿主 Codex 及其 code-mode-host（如果提供）复制到本 Home 的 runtime/codex-host-VERSION/，保存 SHA-256 清单；up 在启动任何控制进程之前检查文件、版本与完整性。HTTP 健康并不等于 Agent 可启动，status 另提供 codex_available 文件可用性指示。

2026-10-09 修复了旧配置直接引用 Homebrew Caskroom 版本路径的问题：系统升级清理旧版本后，服务仍能提供页面，但新 Run 报 resolve Codex executable。旧 Home 可用下面的显式修复下载同一固定版本的官方 npm 平台包、校验 dist integrity 并独立保存；也可通过 --codex 指定相同版本的已安装 binary。不会自动升级 Executor、改模型、切换凭据或重投失败消息。

# 先确认没有活动 Run；stop 不删除 Workspace 卷、会话或凭据
python3 scripts/opensandbox/local.py stop
python3 scripts/opensandbox/local.py repair-codex
python3 scripts/opensandbox/local.py up

# 可选：使用已经安装的同一版本，而不下载
python3 scripts/opensandbox/local.py repair-codex --codex /absolute/pinned-version/codex

修复前的 profile 保存在 runtime/profile.before-codex-pin.json。不覆盖已有但校验不符的运行时；发现被修改的文件时拒绝启动，由 Operator 检查。宿主系统的常用 Codex 仍可独立升级，Feynman 自己的运行时升级应连同 Executor 兼容性另行验证。

修复后已在原 Local Sandbox Smoke 的同一个 thread 中，用公司 gpt-5.6-terra / max 做只读验证：原生 shell 读取测试文件、执行 unittest，1/1 通过。失败的用户消息没有自动重投。回归覆盖上游 binary 被删除后实际 Rust/CLI 仍能完成 Run，以及页面显示失败原因而不自动重试。

容器可以停止，项目卷保留。

python3 scripts/opensandbox/local.py cli -- workspace stop PROJECT_ID
python3 scripts/opensandbox/local.py cli -- workspace resume PROJECT_ID

# 到期或丢失后重建容器，沿用已绑定的项目卷
python3 scripts/opensandbox/local.py cli -- workspace restore PROJECT_ID

# 只停止本测试 Home 的控制进程，不删除容器、卷、数据库或凭据
python3 scripts/opensandbox/local.py stop
python3 scripts/opensandbox/local.py up

workspace stop 使用 OpenSandbox pause；Docker pause 保留内存，不等于释放全部主机资源。默认容器租期 30 分钟，活跃 Run 由现有机制续期；空闲到期后容器终止，项目卷保留。恢复不保证保留内存进程，文件才是持久部分。仅停控制进程不会强杀容器，停机期间到期清理不作保证。

本地 Server 的 SQLite、来源历史和整个 Codex Home 必须一起备份；Docker 项目卷仍需单独备份。重启 Docker Desktop 后需重新确认服务和 Workspace 状态，不将它视为云端高可用保障。

适合单用户验证，不是强安全隔离。

沙盒只有 Project 命名卷；不绑定宿主源码、Codex Home、DWS auth 或 Docker socket。端口限定 127.0.0.1，drop_capabilities=ALL、no_new_privileges=true，非 privileged。Docker 控制权仅由本机 Operator 持有；模型与 Agent MCP 不提供任意 Docker 管理操作。

原生 Executor 在容器内使用 outer-sandbox-only 模式；这不是 gVisor，也不是强租户隔离。本机 Docker 管理者仍能访问容器与卷。应用秘密经批准后对该工作进程可见，同一个有执行权的 Agent 不能被保证看不到已注入秘密。

固定 0.2.3 通过进程内兼容覆盖将发布端口限制为 loopback，不修改安装包或 Docker daemon。macOS 的 proxy 使用 host-mapped 端口而非不可达的容器 bridge IP；参考 OpenSandbox 官方配置及单主机网络说明。后续升级应重新验证协议、发布地址和 Executor 兼容性。

旧版代理的 macOS 兼容。

0.2.3 的 proxy 路由硬编码 resolve_internal=true，不能仅靠新版文档中的 [proxy] 配置解决。本地启动器同时将该 Docker 端点解析固定到 host-mapped loopback，避免不可达的容器 bridge IP；修改仅在专用 Python 进程内生效。local_smoke.py比较相同路径的直接与代理 HTTP 状态，并实测快照装载，防止再次退化为 502。新版配置文档不代表旧版已实现该配置。
