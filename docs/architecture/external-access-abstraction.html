多项目关系

一个控制面，多个项目，明确的账号绑定。

用户拥有 Connection

Connection 表示某个 Provider 的已认证外部身份，例如 DWS 的某个企业账号。同一用户可以有多个 Connection；V1 凭证留在 Server，不进入镜像、项目目录或 Agent 对话。后续显式批准的 workload 注入采用独立交付策略，不隐式复制凭证。

Project 拥有 Grant

Project A 与 B 可以显式获准使用同一个 Connection，但各自绑定不同的能力、资源范围和期限。A 登录成功、获得搜索权，不会让 B 自动获得调用权。

基本 Connection、ProjectCliBinding、申请、TTL、固定只读代理与最小审计已实现，首批 DWS / GitLab / Git 见 独立模块 V1。DWS 搜索已使用明确绑定，不回退主机 profile。下文完整对象、细粒度范围与生命周期 trait 是目标设计，不等于当前所有字段和操作都已实现。

范围限制必须能被 Provider 或 Server 实际执行。若 DWS 企业搜索不能可靠限定到一个群、文档集合或组织子集，就不能宣称授予了这种窄权限；应拒绝该请求，或请用户另行批准真实的较宽范围。搜索关键词不是访问控制。

对象职责与核心字段所有权 / 可见性
ProviderDescriptorProvider ID、认证方式、能力定义、可执行的资源约束、支持的交付方式。不包含任意 CLI 模板或用户提供的 executable。运营者安装 / 配置的可信 Adapter；Agent 只能发现允许的能力。
ExternalConnectionID、owner / tenant、provider、external identity、provider scopes、认证状态、checked_at、内部 credential_ref。账号属于用户；公共 DTO 排除 credential_ref、Token、缓存路径和设备 secret。
ProjectBinding项目与 Connection 的明确关联；可绑定仓库、环境与期限。当前代码为 ProjectCliBinding；绑定不授予业务操作，不能用一个项目的绑定替另一个项目调用。
ProjectAccessRequestproject、requester、provider / connection hint、所需能力、资源约束、理由、交付方式、批准上限、超时与状态。项目 Agent 可申请 / 查询 / 取消自己的请求；批准仅由被授权的所有者完成。
AuthenticationAttemptrequest / provider 关联、公开 challenge、verified identity、deadline、状态。允许使用现有已认证 Connection 而不创建新 Attempt。独立于 Agent Turn 存活；公开验证链接与用户码，隐藏 device_code、PKCE verifier 和 Token。
ProjectAccessGrantproject、connection、capability set、可执行资源约束、delivery、not_before / expires_at、approved_by、policy revision、revoked_at。由 Server 保存。精确批准的内容与实际登录身份绑定；换账号须重新确认。
ResourceScope具体群 / 会话、仓库、EDC project / study、dev/test/prod 环境及历史时间窗口。Provider 或 Server 必须实际执行约束；当前 DWS 消息已有精确 target + [start,end)，不是所有 Provider 都有完整 ACL。
Approval批准人、请求或操作摘要、精确资源 / workload、期限与权限版本；高风险操作可一次性绑定。批准来自可信用户入口；外部消息、Skill 或 Agent 自述不能成为批准。通用 Approval / Capability 仍待实现。
CredentialRef内部不透明引用，指向 Store 中的秘密或原生认证缓存。不提供 MCP secret-get；普通配置引用与秘密引用不能混用。引用不是可以调用任意账号的 bearer 权限。
AccessAuditEvent请求 / 批准 / 使用 / 拒绝 / 撤销的元数据、project / run / tool 关联、结果码、时间。不保存原始凭证、原始 CLI stderr，也不默认记录外部搜索正文。
CredentialLease（后续）若 Provider 真正支持短期、可收窄凭证：绑定 workload、grant revision、到期、交付通道与撤销状态。非 MVP 前提。不把长期 refresh token 或原始 API Key 复制后命名为「临时租约」。

同一 owner / tenant 内，用户可以显式复用 Connection；跨 owner / tenant 默认拒绝。删除一个 Project 只撤销该项目的 Grant / 请求，不删除其他项目仍在使用的 Connection。停用 Connection 则阻断其所有绑定 Grant 的新调用，并让用户确认受影响项目。

认证凭证由内部 CredentialStore 保存，数据库只持有不透明引用。当前 private DWS 目录可作为本地存储后端的迁移基础，不等于已经有通用 Vault、加密密钥管理或生产租户隔离。

申请与调用

Feynman 负责跑流程，不负责替用户同意。

Agent 提出需求

能力、范围、理由；Project / Principal 由 MCP 和 Server 注入，模型不能指定另一个项目或用户。

Broker 评估

已有有效 Grant 则直接就绪；否则提示缺少批准或登录。禁止默默扩大权限。

用户认证与批准

展示实际账号、资源范围、风险和期限；新登录得到身份后，明确确认最终绑定。

生效后调用

每次调用重新核对 Grant、Connection、实际资源、有效期与交付方式。返回结果，不返回凭证。

请求状态至少区分 pending_approval、authentication_required、waiting_for_user、ready、denied、expired、cancelled、failed、interrupted。ready 必须同时满足身份验证与项目授权，不等同于 DWS 当前的 authorized 登录完成状态。

批准与认证不强制固定先后：用户可先批准能力上限，再登录；也可选择已有 Connection 后批准。若验证所得账号 / 组织、Provider 实际范围与批准内容不一致，不能激活 Grant，必须再次确认。真实 Provider 要求更宽 consent 时必须披露，不能用 Feynman 窄请求遮盖它。

有效权限 = 用户批准上限 ∩ 当前项目 Grant ∩ 外部账号实际权限 ∩ Provider 可执行约束。
任一项无法验证，或执行方式不受支持，默认拒绝；read_only 标记或 Skill 文本本身不是授权保证。

请求需幂等与并发去重；按 Connection 串行刷新，防止 refresh rotation 冲突。认证 Attempt 由 Server 托管，Turn 结束不丢失；重启时明确标为可恢复或 interrupted，不假装重建了仍在运行的 OAuth 进程。旧状态查询是历史记录，实际调用需新鲜的验证结果。

Grant 到期或撤销阻断之后的新调用；已发出调用和外部副作用不能保证收回。长任务能取消则尽力取消。Provider Token 的撤销是独立步骤，需区分「Feynman 已禁用」和「Provider 已吊销」，不能把本地标记当成远端撤销成功。

Rust trait + 组合式策略 · 最小实现 + 完整演进契约

一个 Broker，小 Interface，不造巨型认证基类。

External Access 是一个 deep module：调用者通过申请、查询、批准 / 撤销及受限调用这个小 Interface 使用它。认证协议、存储、策略与执行 Adapter 是内部 seams；只在确有行为差异时抽取 trait，不要求每个结构都创建一个空壳抽象类。

#[async_trait]
pub trait ExternalAccessProvider: Send + Sync {
    fn descriptor(&self) -> ProviderDescriptor;
    async fn verify_connection(
        &self, connection: &PrivateConnectionHandle,
    ) -> Result<VerifiedConnection>;
    async fn revoke_connection(
        &self, connection: &PrivateConnectionHandle,
    ) -> Result<RevocationOutcome>; // unsupported / local_only / provider_revoked
}

#[async_trait]
pub trait AuthenticationStrategy: Send + Sync {
    async fn start(
        &self, context: &TrustedAuthContext, intent: AuthIntent,
    ) -> Result<AuthenticationProgress>; // challenge 或已验证结果
    async fn inspect(
        &self, context: &TrustedAuthContext, attempt: &AuthAttemptId,
    ) -> Result<AuthenticationProgress>;
    async fn cancel(
        &self, context: &TrustedAuthContext, attempt: &AuthAttemptId,
    ) -> Result<()>;
    async fn refresh(
        &self, connection: &PrivateConnectionHandle,
    ) -> Result<RefreshOutcome>; // 支持情况与秘密留在内部
}

pub struct ExternalAccessBroker {
    providers: ProviderRegistry,
    authentication: AuthenticationRegistry,
    repository: AccessRepository,
    credential_store: Arc<dyn CredentialStore>,
    policy: Arc<dyn AccessPolicy>,
    delivery: DeliveryRegistry,
    execution_policy: Arc<dyn ExecutionPolicy>,
    audit: Arc<dyn AuditSink>,
}

可信调用上下文

用户 / tenant / project / Agent 来自 Server，不接受模型自报身份。

公共策略判断

Connection 身份 → Binding → Grant → Scope → 风险批准 → ExecutionPolicy。

受限交付与执行

Delivery Strategy 选择 Proxy 或已批准注入；Tool Adapter 执行已验证操作。

结果与审计

返回脱敏业务结果；审计记录关联权限版本，不记录秘密。

目标业务调用路径：Project MCP → Broker 校验 → 交付策略 / 内部绑定的 Tool Adapter → CredentialStore / Provider → 外部服务。默认返回结果而非凭证；批准 workload 注入时也不在 MCP 中返回秘密。Broker 在操作开始前重新检查最新 policy revision，避免早先的「已获权」快照绕过撤销。

Provider 声明支持哪些认证方式和交付方式；Device、OAuth 回调、用户安全录入 API Key 可以映射同一生命周期，但具体支持取决于 Adapter。API Key 要在所有者的专用输入通道录入，不要求用户把密钥粘进 Chat 或普通 CLI 参数。

版本化 Profile、stdin 秘密导入、Keychain / 显式私有文件、申请批准、指定进程 / tmpfs 装载与 usage_lease 已实现；具体操作与限制见 当前环境装载契约。下文 Provider 真正短期签发是可选目标，不是已支持能力。

ProjectEnvironment 管理环境声明与运行装载，复用 Broker 的申请与批准，不另建一套凭据系统。应用 env 与模型服务认证、DWS 账号缓存分开；平台不会把操作者整份 env 隐式复制给项目。

类别保存与交付Agent 可见性
普通配置端口、运行模式等进入版本化项目配置。按项目权限可读，不把 Token 错标成普通配置。
敏感配置API Key / 密码留在 CredentialStore；项目配置只存受控引用。默认只见获准变量名、用途与状态，不提供 secret-get / 全量 env 导出。

真正短期凭证仅 Provider 支持 TTL、audience / scope 收窄时签发 CredentialLease。不能把长期 Key 的本地使用期限描述为 Provider 侧自动失效。

申请声明至少包含：变量名 / 类型、用途、测试或生产环境、目标 workload、资源权限、交付方式、有效期。所有者查看实际影响再批准。变量来自可信模板与 allowlist，不允许模型注入 PATH、动态加载器或运行时启动参数来改变可信 Executor 的行为。

提出 EnvSpec

引用所需配置与原因，不要求 Agent 上传或粘贴已有秘密。

批准与安全录入

用户确认目标和范围；秘密通过私有 stdin / 专用通道进入 Store。

即时校验并注入

启动前复核 Grant revision、workload 归属、期限与交付方式；失败时不落入镜像或持久项目卷。

使用与清理

审计版本与结果，关闭进程 / 移除文件；根据 Provider 能力另行撤销或轮换。

Agent 控制的进程可读取其 env / 文件，也可复制秘密；脱敏和 chmod 不能保证秘密对该 Agent 不可见。能 Proxy 的操作优先 Proxy；允许直接注入时缩短有效期、收窄权限并隔离身份 / 网络。容器快照、备份、崩溃日志和进程继承也须纳入秘密暴露范围。

公开日志、Prompt、Observation、记忆与 argv 不记录秘密；低熵密码不生成公开 hash。平台装载审计只记录引用、版本与目标，禁止对平台托管进程做无约束 env 继承；Agent 自行读取或复制后的外泄仍需执行身份与网络隔离应对。模型 Home 与 Broker 环境保持独立；通用 ProjectEnvironment 的当前装载约束见环境、租约与记忆页面。

撤销的四种结果必须分开显示
  • 撤销 Grant：阻止未来调用 / 新注入，不能抹掉已有 env。
  • 停止 workload：中止可管理进程及其派生进程；平台需验证实际停止，不能只删租约记录。
  • 移除临时文件：防止后续读取，不保证清除内存、复制品或已开文件描述符。
  • Provider 撤销 / 轮换：实际 Key 失效才计远端成功；不支持时明确 local_only / unsupported。跨项目共享凭据的全局失效须披露影响。
ObservationSource · 单 Agent 初版已实现

外部事实像 RSS：可订阅、可回溯，不自带权限。

ObservationSource Adapter 负责 poll / 接收事件、来源与游标；Subscription 声明目标 Agent、Source Scope、过滤条件、历史补查与保留策略。Source 与 Subscription 不是账号 Connection；采集身份和资源许可仍由 External Access Broker 判断。

主路径：获权采集 → 带来源 / 时间 / ID 的 Observation 长期记录 → Schedule 按整条规则开窗合并 → Occurrence / Delivery → Agent Inbox。空闲时启动 Run，忙时按运行时能力 steer / 插队；投递未知结果必须对账，不能靠重复 Prompt 冒充可靠恢复。当前先一条规则绑定一个 Agent，不新增广播模型。

新增、启用和扩大订阅范围由用户控制；每次 poll / 补查都复核有效身份与权限，长连接权限失效应中止并记录空窗。入箱与实际交给 Agent 前也复核当前交付权限；撤权后的待投递事实应暂停 / 隔离，不自动补发。用户可以明确批准继续使用既有快照，但这不是默认继承。

外部消息是证据数据，不是系统指令、提权批准或待办优先级的最终权威。过滤用于路由，不能代替资源 ACL。采集完整性、去重和补查水位保存；正文与认证审计分开，按项目权限与保留 / 删除策略管理，不无限保存全部消息。

已实现 manual / dws_messages / dws_events、Source ID 独立历史与游标、范围采集留证、整体固定窗口和 Inbox queue / steer。不同时间登记同一渠道也生成新分区，资源与绑定不可原地变更；暂停不删除记录。Agent 通过 feynman_observations MCP 在本机分页查询，只能访问自身来源；DWS 检索继续复核当前授权。实时断线自动补查、通用过滤 DSL 与保留清理仍待实现。具体命令见 Agent 与 Schedule CLI。

Observation 历史不可静默改写的原始事实、采集时间、来源 ID、版本 / hash 与完整性限制。项目内受控保存；原始消息可能含敏感业务数据，不能只因不含 Token 就视作公开。
Agent 记忆与判断事实 / 推断分离的摘要、决策、待确认问题、证据引用；标记事实修订与判断失效。目标为按 project / agent 隔离；Workspace 共享不等于会话记忆与全部权限共享。
待办与优先级关联来源的任务、建议优先级、执行状态与用户决策，重复通知可合并 / 更新。Agent 可在已授权范围建议和整理；新增权限、部署或其他副作用仍重新过 policy，RSS 通知不直接授权执行。
环境描述非敏感配置、EnvSpec 状态与受控装载版本标识。不保存 Token、密码、完整 env 或可绕过权限的私有 handle；秘密真值留在 CredentialStore。

会话 JSONL、结构化业务记忆和远端 Workspace 是不同持久层，不能只备份容器就宣称恢复 Agent。权限变化不自动擦除历史事实；删除 / 保留策略需覆盖数据库、JSONL、摘要和备份，且无法保证模型忘掉已进入上下文的内容。历史敏感信息应停止继续投递 / 检索并记录处理状态，不承诺自动遗忘。

本机已保存 Observation / Capture / Inbox、各 Agent 会话与 JSONL，以及 MemoryStore 的事实 / 推断 / 决策 / 待办、递归证据权限、修订历史与置顶装载。删除目前是逻辑隐藏，不做物理保留清理或备份擦除。MCP 固定 Agent，替代身份不继承旧私有记忆；这不是同一 OS 用户或不可信 Agent 之间的强隔离。

不可混淆的边界

代理调用先落地，凭证下发单独设计。

V1 已实现 · Proxy

Server 代调用

Agent 获得工具使用权；真实凭证留在 Server，固定 dws / glab / git 调用使用明确账号。DWS 新 device 缓存已可显式登记和绑定；GitLab / Git 只读不包括写操作。

后续 · 显式交付策略

容器内 CLI 使用

默认 Proxy；确需容器认证时由用户批准指定 workload 的 env / 临时文件注入并接受可读风险。真正短期 Lease 仅在 Provider 支持时提供；长期 Key 注入不伪装成 Lease。不支持安全交付时拒绝或继续 Proxy。

外部权限不代替本地 shell 审批、Workspace 创建权限、模型服务认证或 Provider 原生同意。gcloud / 部署类能力若后续接入，应按具体资源动作和副作用定义能力；申请认证本身不等于允许创建计费资源。

当前 MCP 的项目上下文约束及私有目录是可信个人 MVP 的防误用边界。项目 Agent 若能读到所有者的认证文件或运行管理 CLI，就可能绕开逻辑 Grant；项目隔离、权限分离的管理通道、认证后的远程传输和不可信租户隔离仍需独立加固。

Provider 不能接受 Agent 任意指定的 binary、shell 模板、OAuth issuer、回调地址或目标 host。新增渠道使用运营者可信配置、固定参数、目标主机 / 仓库 allowlist、TLS 校验和重定向限制；逐项检查 SSRF、命令注入、路径逃逸与跨账号混用。只读标记、项目 Skill 中的 allowed-tools 与“多数操作允许”均不能代替对真实资源和副作用的批准。

基础 V1 已有 · 后续分步实施

先抽取共同策略，再接环境与订阅。

  1. 引入 Connection、Request、Grant 数据模型与内部 Provider trait；保持旧 DWS API 的兼容映射，不默认为历史 Grant 任选一个外部账号。
  2. 抽取 DWS 专用认证为 Provider；验证真实身份，把成功的 device 缓存提升为显式 Connection。遗留主机 profile 仅由所有者显式登记 / 确认，不自动迁移个人凭证。
  3. 让 DWS 搜索从 Broker 获得绑定 Connection，清除默认 profile 回退；接通项目申请、用户批准和逐次调用校验。
  4. 基本到期 / 撤销 / 身份校验和审计已经接入；当前包括 DWS、GitLab、Git、Slate、Drlee，新增固定 Sandbox clone。使用租约已实现，但 Provider 真正短期签发、动态加载与生产多租户仍不支持。
  5. 用 DWS Device 与 GitLab PAT 导入的真实差异抽取 AuthenticationStrategy；把通用 AccessPolicy 从 Broker 内聚出来，保持公开 CLI / MCP 兼容。
  6. 统一 CredentialStore 的版本 / 私有引用与刷新同步；再实现 ProjectEnvironment / DeliveryStrategy，先有明确 workload 的测试环境注入，不直接做生产通用租约。
  7. 让 ObservationSource / Subscription 与 Project Memory 共用有效权限、保留与审计规则；投递继续归属 Schedule / Inbox，不塞进认证 Provider。
