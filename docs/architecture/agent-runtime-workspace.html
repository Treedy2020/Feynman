Feynman Control Plane / CLI-First Architecture

用户通过 CLI 接入中心，
Agent 在受控工作区调用工具。

Rust Feynman Server 管理多租户身份、项目权限、外部连接和凭证；常规用户通过 CLI 使用中心服务，Agent Runtime 通过 MCP 调用受限工具。Agent 的可恢复 Workspace 不持有外部源凭证，项目应用及主要依赖可以独立运行在云端。

01 CORE PRINCIPLE
凭证属于 Feynman 管理，不属于 Agent Workspace。

Server 是身份、工具授权和连接状态的中心；Sandbox 可暂停、回收和重建。

01 / COMPONENT MAP

中心服务管理身份和工具，Agent 各自拥有工作区

用户 CLI 与 Agent MCP 是两种不同入口；Feynman Server 执行租户与项目授权，Sandbox Runtime 只承载 Agent 会话和工作文件。

MODEL / 01 持久化的是 Workspace

稳定的 Workspace 身份和文件状态可恢复；底层容器算力可以暂停、回收和重建。

MODEL / 02 应用不必跑在 Workspace

Agent 可以在本地工作区做少量修改，通过 Staging URL、日志和项目工具验证远端应用。

MODEL / 03 Session、Workspace、Run 各有生命周期

长期 Agent 连续性由持久记录支撑，不依赖某个永不退出的进程。

IMPLEMENTATION STATUS

Rust CLI / Server 的本地纵向切片已实现 Project 管理、租户作用域 SQLite、持久本地 Workspace、Codex App Server 对话及可续读的 Agent Run 事件。Codex 使用 workspaceWrite 沙盒、Project Workspace 文件范围、关闭沙盒内网络并通过原生 onRequest 审批处理越界命令。当前身份仍是固定的 local dev Principal，Server 强制 loopback；正式用户认证、远程多租户服务、中心凭证管理、Feynman MCP 工具模块、GKE Agent Sandbox、gVisor、Workspace PVC / Pod Snapshots、Generator / Reviewer 双运行时及正式外部源 Adapter 尚未接入。Agent Session 已与 Agent Run 分开建模，但 Heartbeat / 定期唤醒接口尚未启用。上图其余部分展示的是目标架构；初期用户界面为 CLI，不包含 Web GUI。
