各自收信，统一查看，按需唤醒。

一个 Source 注册实例就是一条 Observation Channel。不同人、群或日志来源各自保留身份与历史，项目 Feed 汇总当前可读取的消息。终端窗口只是视图，不拥有采集器。

Observation Feed 是外部原始消息收件视图；现有 Agent Inbox 是 Prompt 投递队列。查看不启动模型。当前 CLI 每秒增量读取本地历史，不是 SSE；不会为每个窗口重复开启 DWS 连接。

机制实时窗口独立进度权限与恢复CLI / MCP验收

采集、查看与投递，各自独立。

EDC UAT     ── 渠道 A ─┐
公式讨论群   ── 渠道 B ─┼── 持久 Observation 历史 ── Project Feed
项目联系人   ── 渠道 C ─┘          │                    ├─ 统一终端窗口
                                  │                    └─ 单渠道终端窗口
                                  └─ Schedule 固定开窗
                                      └─ 聚合通知 → Agent Inbox → Agent

Feed 直接读取 Source 的历史分区，不复制消息或新增可变 Channel 注册。原生事件由 Server 托管长连接，历史查询型来源按 Source 的 poll_seconds 定期采集。查看窗口不能改变采集模式或覆盖保证。

开窗口只多一个查看者。

sources watch 展示选定渠道；feed watch 展示项目当前获权渠道的统一流。同一渠道可同时开多个窗口。默认从连接成功时的最新持久位置开始；--after 0 先回放保留历史，其他 --after 值用于续看。

--json 输出 JSON Lines，逐条保留 source_id、持久 sequence、来源时间、入库时间和完整受限记录。人工视图显示 sequence、来源时间、渠道名称与正文预览，转义终端控制字符并限制预览长度。channels 事件展示 enabled / listener_state / coverage / poll_seconds，不把 paused 或 gap 宣称为实时在线。

关闭不 pause Source；打开不 resume Source；查看不产生模型 Turn，不改变 Schedule 水位，不确认或取消 Agent Inbox。管理采集仍用独立命令。

四种进度，不共用一个“已读”。

进度含义
Source 游标外部历史连续覆盖到哪里。
终端查看位置本地输出到的 sequence；next_after / has_more 分页。
Schedule 水位固定收集窗口已消费哪批新事实。
Agent Inbox 确认运行时是否接收聚合 Prompt，不代表任务完成。

Feed 按入库 sequence 排序；迟到补查记录仍能被续看，occurred_at / observed_at 分别保留原始时间与收取时间。同一 Source + event_id 去重，不同注册不合并历史。

查看位置当前由查看者保有，关闭时显示续看位置，重开需传 --after，不新增全局人工已读表。游标只应复用于同一 Project 与筛选范围；新获权来源的旧记录可单独 --source / --after 0 回看，不自动混入已越过的统一游标。

每次读取重新复核授权。

权限过滤先于正文、分页、数量和游标返回。统一 Feed 排除不可读取渠道；显式查看无权来源失败关闭。Agent MCP 只读取其固定身份的来源，新 Agent 不继承旧身份的历史；所有者可检查保留的 manual 证据。

CLI 仅连接 loopback HTTP，不走代理或重定向。连接错误、429、5xx 用 1 / 2 / 4 … 最多 30 秒退避重试，只重试读取，保持位置；拒绝访问、注册不存在或响应无效则停止，不自动认证、创建或恢复来源。Ctrl-C 可在等待中退出。

读取来自持久历史，不依赖内存广播；Server 重启后从原位置续看。现有 DWS 断线仍会留下 gap，自动历史补查尚未实现，流式显示不是外部零遗漏承诺。撤权不能保证已展示内容或已有模型上下文遗忘。

当前公开接口。

feynman feed read PROJECT_ID --after 0 --limit 100
feynman feed watch PROJECT_ID
feynman --json feed watch PROJECT_ID --after SEQUENCE

# 独立窗口，可在不同终端同时运行
feynman sources watch PROJECT_ID SOURCE_ID
feynman sources watch PROJECT_ID SOURCE_ID --after 0
feynman feed watch PROJECT_ID --source SOURCE_ID --poll-seconds 2

# 管理采集，与查看分开
feynman sources pause PROJECT_ID SOURCE_ID
feynman sources resume PROJECT_ID SOURCE_ID

# Agent 一次有界读取，不挂住模型工具调用
feynman_observations {"operation":"feed","after":0,"limit":100}
feynman_observations {"operation":"feed","source_id":"SOURCE_ID","after":SEQUENCE}

GET /v1/projects/PROJECT_ID/feed?after=0&limit=100
GET /v1/projects/PROJECT_ID/feed?head=true
GET /v1/projects/PROJECT_ID/agents/AGENT_ID/feed?after=0

增量查看间隔 1..60 秒，默认 1 秒；只影响本地读取，不能使历史采集型 Provider 比自身轮询更实时。事件型 Schedule 仍按整个 Schedule 的 collect_for_seconds 固定开窗，投递状态机不因查看端增加而改变。

公开接口验收。

5 个 Feed / 窗口集成测试已通过：来源分区、跨项目隔离、分页去重、多窗口、关窗不停止 DWS、断线续看、Agent 更换与撤权后的过滤。DWS / 模型为离线夹具；没有读取真实 EDC 消息。

EDC 可视化为独立内存模拟，展示单渠道、统一收件视图、固定窗口和 Agent 通知，不是已连接后端的 GUI。
