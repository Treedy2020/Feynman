以 Project 为工作区，Console 让项目可看也可管。

Feynman 仍是 local-first 的多项目管家。Console 的根对象是 Project：先进入项目，再管理其 Agents、Schedules、观测信息源、Workspace 与活动；选择某个 Agent 才进入它自己的长期 Conversation。Console 与 CLI 复用同一 Rust Server 的状态和权限规则。

消息链路当前行为不会隐含发生
人工输入发送时立即显示“发送中”，HTTP 持久化后显示接收状态；默认 steer_if_active，支持明确排队。审批、启动中或不可 steer 时保留等待状态。“已收到”不代表模型立即回答；网络写入结果未知不会自动重试。
项目 SSEGET /v1/projects/:id/stream：先完整持久快照，再推送文本／工具增量、审批及 Inbox 变化。重连重新加载权威快照；按事件 ID 去重。聊天连接正常时停止原有 2 秒轮询；其他管理和来源视图仍轮询。不是 Codex 直连；不把用户输入或秘密放到 URL。浏览器用 fetch 流和 CSRF header。
消息中心GET /v1/notifications 返回持久提醒、单独已读标记和业务处理状态；按全局单调 sequence 分页。UI 展示最近 100 条；API 可补查历史。消息中心不是 Agent Inbox 或外部 Feed；已读不批准、验收或重放任务。
通知 SSEGET /v1/notifications/stream 支持 after / Last-Event-ID 补齐；首次从 head 开始，不重放旧横幅。原生进程独立订阅，关闭窗口不影响接收。通知不以易丢的内存广播为事实；广播仅唤醒读取 SQLite。

统一 attention record，而不是每个功能自己发送横幅。

当前事件 run_completed / run_failed / run_interrupted / approval_requested 与 ChatEvent 同事务追加到 attention_events；attention_reads 单独记录用户已读。文本增量与对应 ChatEvent 同事务提交；会话快照和 Run 游标在同一读事务中读取，避免恢复期间重复或漏接文本。慢 REST 读取不能覆盖已经推送的新状态。提醒包含 Project、Run、kind、创建时间与稳定 ID，不保存 Prompt、命令输出或 Token。审批是否仍待处理由实际 Run／approval_resolved 重新推导。只记录升级后的新事件，不回填历史横幅。

系统通知默认关闭，由菜单栏显式启用，偏好保存在 macOS 应用数据目录。横幅只含项目名与事件类型；一个批次超过 3 条会合并提醒。重连利用单调游标去重；单实例插件防止重复客户端提醒。原生横幅不提供批准按钮，也暂不保证点击定位某个 Project；应用内“打开项目”会精确进入其会话并显示当前审批。原生页面不授予远程 WebView 文件／shell／凭据 IPC 权限；HTTPS 授权链接在系统浏览器打开。

通知调用成功仅表示已交给系统，不能证明用户看见。Tauri 桌面插件的 permission_state / request_permission 当前返回 Granted，并不反映 macOS 实际设置；用户需通过“发送测试通知”和“macOS 通知设置”确认。专注模式／系统禁用会抑制横幅，但消息中心记录不受影响。桌面通知按钮与动作能力不在本版承诺内。参考 官方通知插件及 系统托盘文档。

前后端 seam

Console 与 CLI 是同一个领域接口的两个 Adapter。

Rust Server 持有项目、会话、收件箱、授权与审计的事实源。CLI 和浏览器都只调用它的受控接口；Console 不读 SQLite 或 Codex JSONL，不独立拼接 DWS 命令，也不复制调度逻辑。前端的主要工作是将后端对象、因果关系和恢复动作清楚呈现。

数据面现有接口下一阶段需要的接口
系统接入目录与来源聚类GET /v1/access/providers、GET /v1/access/connections；项目内 GET /access、GET /external-tools 与 GET /sources。当前目录和聚类已接入；不等价于真实 Provider 健康、完整认证 UI 或任意 CLI 代理。
项目列表与项目状态GET /v1/status、GET /v1/projects、GET /v1/projects/:id/status全局项目列表分页与筛选；Project 概览聚合只在项目路径下返回。
Agent 与会话当前 GET /conversation、POST /messages 都隐含项目唯一 Main Agent。项目下 Agent CRUD / list / select；消息必须显式指向稳定 Agent ID，返回所选 Agent 的 Conversation。
Task 与 RunGET/POST /tasks、GET /runs/:id/events?after=…、审批响应。统一 Inbox、Delivery 对账，以及 Task / Run 与目标 Agent 的稳定关联。
ScheduleGET/POST /schedules、PUT /schedules/:id（启停）。固定 Agent ID、显式改派、窗口／Occurrence／Delivery 查询、DWS 事件规则与有界 backfill。
WorkspaceGET/POST /workspace、POST /workspace/actions。按项目授权的文件列表／预览、变更摘要；限制大小、路径与敏感文件。
观测源与权限Source 列表／历史／监听健康、项目与 Agent 权限校验、GET /feed?after=… 和固定 Agent 的 GET /agents/:agent_id/feed；DWS Authorization 请求／状态检查。把已有接口接入来源列表、单渠道窗口、统一外部收件视图；增量游标独立于 Agent Inbox，撤权后复核读取。

上表中的相对路径均在 /v1/projects/:id 下。设计中的新接口应返回稳定对象 ID、状态、版本／更新时间、来源及下一步可执行动作；列表分页与事件游标由后端负责，避免 UI 从多路数据自行猜测“最新状态”。

正确性与安全

状态可以刷新，权限判断不能留给页面。

实时与恢复

聊天已接 SSE：首次与重连使用持久快照，文本和工具事件按 ID 去重；消息中心使用持久单调游标。聊天推送中停止 2 秒轮询，其他视图仍轮询。页面刷新后不丢审批和投递状态。

敏感与外部内容

浏览器只收脱敏身份和授权范围；Token、认证缓存、原生配置不下发。外部消息与文件正文按不可信内容渲染，禁止把它们当成 HTML 或系统指令。

写操作

创建、停用、批准、撤销、补查等由 Server 复核用户身份与范围；使用幂等键及版本冲突反馈。高风险动作展示影响范围，不能凭按钮是否隐藏来授权。

当前身份仍是固定本机所有者。Console 只接受确切 loopback Host；写请求需同源 Origin、JSON 和每次 Server 启动生成的 CSRF token。CLI 原接口继续拒绝 Origin；Console 的 allowlist Adapter 清除外层路由参数后调用同一领域处理器，不打开通用代理、secret 登记或任意工具执行。响应具有 no-store、CSP 与 frame-ancestors none，防止缓存和嵌入。CSRF token 仅在页面内存，localStorage 只保存主题。服务重启后需重新读取会话；写操作不自动重试。它不是多用户登录或强隔离，不能公开到局域网或 Tailscale。

已实现项目优先导航，项目内的 Main Agent 对话、持久 Inbox、固定展示的审批卡、独立消息窗口与来源登记，Schedule 保存后默认暂停，Workspace 生命周期及已有 Connection 绑定 / Tool Grant。聊天与通知通过 SSE；其他管理视图轮询读取。打开页面不自动创建沙盒、启动来源、运行模型或批准权限。来源关闭窗口不停止采集；撤权后缓存记录根据后端可见渠道重新过滤。

实现位置：crates/feynman-server/src/console.rs 和 src/console/{index.html,app.css,app.js}。Rust 与公开接口测试覆盖 Host / Origin / CSRF、旧 CLI 契约、单会话审批、重启恢复；独立浏览器测试在隔离 fixture 中检查真实点击、窗口分离、外部文本转义和窄屏布局。当前实现只接已有接口，不重造授权、调度或会话逻辑。

  1. Project-first 基础版：Rust 同源托管静态前端；全局显示项目列表／创建和系统接入目录，进入项目后才显示项目概览，再进入唯一 Main Agent 对话；Schedule、Workspace、按来源聚类的授权与 Run 入口留在该项目内。只接现有接口，显示刷新时间及错误。
  2. 单 Agent 领域闭环：随 Agent CRUD、统一 Inbox 和 Delivery 状态机落地，增加 Agent 设置、投递时间线与对账入口；CLI 和 Console 调同一后端接口。
  3. 观测与历史：随 DWS 监听、Schedule 窗口和 backfill 落地，项目内管理来源、资源范围和监听空窗；随后加入受限文件浏览。
  4. 项目内多 Agent：后端支持后开启 Agent 列表与会话切换、按 Agent Grant 和 Schedule 固定目标；Reviewer、Agent 协作与远程多用户再逐步扩展。

首版采用原生 HTML / CSS / JavaScript，由 Rust 同源嵌入托管，不需要 Node 开发服务、前端构建或 CDN。框架不是此架构的关键决策；Console 与 CLI 都复用唯一的后端状态和权限规则。
