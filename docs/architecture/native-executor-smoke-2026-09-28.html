实测边界与安全限制

  1. 内层 bwrap 不可用。 普通 Docker 的限制拒绝创建用户命名空间；带 workspace permission profile 的线程在加载远端 AGENTS.md 时即失败。 未改变 Spark 内核配置、未添加 SYS_ADMIN、未启用 privileged，也未重启 Docker。 本次明确采用远端线程 :danger-full-access，依赖外层 unprivileged Docker/runc 隔离。该模式确实移除内层 Codex 限制，不能当作 workspace-write 的替代安全证明。 官方 Permission Profile 定义。
  2. 隔离检查不是逃逸审计。 无宿主 bind mount、Docker socket、GPU 或认证文件； 容器 drop ALL capabilities、no-new-privileges、1 CPU / 1 GiB。 仍是共享内核的 runc，不是 gVisor/微虚机或生产多租户隔离。
  3. Executor listener 是受信任测试接口。 容器内 44773 不发布到宿主；本机 经 SSH 转发访问其 bridge 地址。该原生 listener 无额外认证，不能暴露到公网或 与不可信 workload 共用的可达 bridge 网络。生产需独立网络与认证边界。
  4. 恢复由 operator 实施。 容器更换后重新复制 Executor 并注册连接；app-server 更换后重新注册环境，再 thread/resume。尚未实现 Feynman 的自动生命周期恢复。
  5. 持久化不是进程 checkpoint。 /workspace 文件由 Volume 保留，中央会话由 本机 Codex runtime home 保留；容器根文件系统、PTY、正在运行的进程和任意系统 安装状态没有被承诺恢复。客户端 fs/*/process/* RPC 也没有被验证为远端 API。
  6. 原生事件形状需兼容。 本版本派发使用 subAgentActivity(kind=started)；不能 只识别旧 collabAgentToolCall(tool=spawnAgent)。只取 final_answer 作为答案， 避免把 commentary 混入结构化验收结果。

清理与复跑

已删除本次测试容器与 named volume，停止临时 OpenSandbox 服务、本机 app-server 和 SSH tunnels。独立检查无 fixture-labelled 容器/volume，Spark 的 18080/44773 无宿主 listener；原 uptime-kuma 仍健康。没有创建 GKE 或使用 GPU。 测试 Volume 中只有 dummy Workspace 数据，删除不可恢复；日志、包缓存和私有 会话证据仍保留，且无临时认证链接。

复跑方法见 Native Executor Smoke 操作说明。

对 Feynman 下一步的影响

可以优先复用原生 Executor，不必自建 Shell/apply_patch/Sub-Agent 工具集合。 接入 Rust 产品前仍需实现：持久化项目/会话与 Volume、环境 ID 的关联；容器地址 变化后的原生连接重新注册；启动时同一 thread 的恢复；连接状态与 Session Heartbeat 的映射；断线/超时可见性；生产隔离与凭证边界。

外部观测渠道的凭证仍由中心 Feynman broker 管理。长期独立 Reviewer 需另一个 Session/Workspace，不能因为普通 Sub-Agent 共享环境已通过，就将 Reviewer 也接到 Generator 的可写现场。
