公共参考 · 通用模型 + V1 边界

认证证明账号，授权决定项目能做什么。

这里说明跨 CLI 的共同规则，不把 DWS 专属命令和状态复制成“所有工具都支持”的接口。Provider 决定如何认证；Feynman 决定哪个项目、哪个账号、什么操作、何时可以调用。

共同概念

不要把三个许可合成一个“已登录”。

层次证明什么不证明什么
外部账号认证Provider 已验证某个真实用户 / 组织账号；可登记 Connection。不自动授权任意项目，不保证账号能访问指定资源。
项目绑定与业务 Grant项目明确使用哪个账号、仓库和有效期，并允许固定业务能力。不扩大 Provider 实际权限，也不隐含任意 CLI、写操作或部署权限。
执行环境与审批允许 Agent 在指定 Workspace 执行被批准的本地操作。不隐含外部登录、云资源创建、凭证下发或远端发布权。

Skill 说明工具怎么用，不是授权证据。镜像装有 CLI 也不表示已登录。同一所有者可以显式复用账号，但 Project A 的登录或 Grant 不自动赋予 B 权限。

公共控制面流程

申请、认证、绑定、批准、逐次验证。

图是理解顺序，不强制唯一顺序：可先授予能力上限，也可选择已有 Connection；实际执行必须同时满足认证、绑定和 Grant。Provider 有单独的登录发起许可时，所有者还要先授予它。

V1 通用 MCP feynman_access 只有 providers / status / request，先需 external.access Grant。它不登录、不录入 Token、不绑定、不 approve。请求持久化 24 小时并去重；所有者用 feynman access 管理账号和绑定，用 external-tools grant / revoke 管理业务许可。

可运行命令见 External Access CLI。更完整的资源 ACL、统一认证生命周期和租约仍是 演进契约，不能当作当前 API。

公共协议参考 · 仅适用于支持 Device 的 Provider

不要求服务端打开浏览器的登录方式。

OAuth 设备授权让无合适浏览器或输入受限的客户端发起认证；用户在另一端打开验证页面并确认，客户端等待授权结果。协议说明见 RFC 8628。

  1. 客户端向 Provider 发起设备授权，取得用户验证信息和私有设备码。
  2. 只向用户展示验证链接、用户码及期限；用户在 Provider 页面核对请求并同意或拒绝。
  3. 原生 CLI 按 Provider 的协议和轮询间隔等待结果；Feynman 不通过前端反复启动新登录。
  4. 完成后验证实际账号，再进入 Connection 与项目授权流程。网页确认和项目获权仍是两件事。
字段 / 数据谁可看到用途
verification_uri / verification_uri_complete该申请的用户 / 项目客户端打开 Provider 的真实验证页面。
user_code / expires_at该申请的用户 / 项目客户端核对本次申请与截止时间；不是可长期分享的凭证。
device_code / Token / app secret私有认证实现不得返回给 Agent、项目日志或 Workspace。

标准设备响应使用 expires_in 等协议字段；expires_at 是 Feynman DWS 适配器的公开截止时间。字段表是交互原则，不声称所有 Provider 都采用 DWS JSON schema。DWS 当前实现见 DWS 设备登录；GitLab V1 使用 Token stdin 或所有者显式原生导入，Git 不提供 device 登录。

公共客户端职责

进度、实际验证、Heart Beat 不要混用。

机制负责者意义
Provider 授权轮询原生认证 CLI等待用户同意，遵循 Provider 的期限与轮询规则。
公开进度读取用户 CLI / 未来前端读取 Server 保存的记录；DWS GET / status 不触发新登录。
新鲜身份检查Provider Adapter / BrokerDWS check 或业务调用重新验证实际账号；按需刷新由工具负责。
Session HeartbeatAgent 运行时（后续能力）存活信号，不证明外部账号有效，也不自动创建任务。

历史“登录成功”与当前“已配置”都不证明 Token 仍有效。V1 configured_not_verified 只代表绑定和 Grant 元数据满足；实际业务调用仍需重新验证。Provider 专属状态保留在子模块：DWS 的 authorized 不能改写为平台已经授予搜索权。

客户端只显示经适配器验证的链接和公开字段，停止展示过期 / 中止的挑战，避免写入浏览器缓存或外部日志。若页面未来接入，不接收任意认证地址、不读取私有配置，不代用户同意。

撤销与失效

取消任务，不等于吊销外部账号。

动作作用范围不承诺
取消认证任务结束本次未完成的登录等待。不吊销已经发出的 Provider Token。
撤销项目 Tool Grant禁止该项目后续调用指定业务能力。不移除其他项目的独立 Grant。
解绑 / 到期该项目不能继续用对应账号 / 仓库执行新调用。不删除外部账号或其他项目绑定。
停用 Connection阻断本地使用此 Connection 的新调用。不声称 Provider 已 revoke Token。
Provider 侧吊销由外部系统实际使凭证失效。当前未实现通用远端吊销入口。

已发出的调用与外部副作用不能保证收回。Server 重启也不等于恢复了 OAuth 进程；各 Provider 应明确哪些状态可恢复。DWS 将未完成流程标为 interrupted，实际规则见 DWS 生命周期。

公共安全边界

结果进入项目，秘密留在控制面。

Agent 只提交能力需求、理由和业务 schema 中的参数，不能任意选择 binary、认证服务地址、私有路径、账号密钥或另一个项目。认证与所有者管理入口不直接暴露为可自行提权的项目 MCP。

V1 为本地可信开发身份，Server 只监听 loopback，凭证保存在私有目录；不是加密 Vault、远程用户认证或强多租户隔离。认证缓存不挂载到 Workspace，不进镜像。受批准的固定 git.workspace.clone 会将凭证经 stdin 短暂用于容器 Git 进程环境；root Agent 可观察它，不能声称恶意 Agent 保密。管理 CLI / MCP 是协议边界，不阻止同一 OS 用户读取文件 / 进程，也不发放伪装成临时租约的长期 Token。

“只读”仍需核对实际资源与 Provider 可执行约束。关键词不是资源 ACL；无法执行的窄权限不能声称已经保证。对接更多外部工具时，应复用这些共同规则，而不是复用 DWS 固定域名、600 秒等待上限或错误码。

当前 Provider 差异

公共流程，不抹平工具的差异。

GitLab 支持所有者显式原生导入或 Token stdin；Slate 使用真实浏览器 PKCE 或选定 Keychain profile 导入；Drlee 使用原生浏览器或单账号缓存导入，独立刷新。Slate / Drlee 新登录由所有者 CLI 保持等待，没有通用后台 device 状态机；Agent request 持久化需求并提示所有者命令，不直接录入密钥或批准。具体命令与边界见 Slate / Drlee / Sandbox Git clone。
