Local-first 多项目 · 当前实现 + 权限设计

一个 Feynman，管理多个项目。

通过 Skill + CLI 创建、调度和沟通各个项目。每项目拥有长期 Main Agent 与独立 Workspace；Feynman 代项目维护认证申请和权限流程。会话在本地，执行在远端，项目获权不自动互通。

已实现 单 Agent + Schedule 投递：用户管理身份与能力、事实源实例独立持久化、整条规则固定开窗、Inbox 排队与原生 steer。可先创建无 Agent 项目。本机可视化工作台已实现；新增 macOS Desktop、SSE 与消息中心，连接同一 Rust Server。多 Agent 与申请类通知仍是后续能力。

外部渠道使用 认证与安全组合策略的最小实现：认证、项目／Agent 权限、私有凭据、Proxy 交付、固定执行与元数据审计分开。事实订阅及本机历史查询已接入；项目环境注入与通用长期记忆仍是目标设计。

多项目管理

Feynman 是管家，不是一个项目的 Agent。

共享控制面

统一创建、查询和管理多个 Project，维护任务调度与用户沟通；为各项目准备执行环境、发起必要的认证与权限申请。

独立项目上下文

每项目一个 Main Agent、Thread、任务队列、Schedule 和 Workspace。可跨项目并行，但不会自动继承其他项目的消息或授权。

显式外部授权

Connection 表示登记的账号，Project Binding 指定账号 / 仓库 / 期限，Tool Grant 指定可调用业务。Agent 提需求，用户批准，Server 每次调用重新检查。

「已登录」不等于「所有项目都可以使用」。同一所有者可以显式复用外部账号，但 A、B 必须分别获权；见 External Access 独立模块。版本化环境装载、使用租约与长期记忆已追加，Provider 真正短期签发仍不支持。

核心约定

管家、项目 Agent、执行环境，各有职责。

本地 Harness 是入口

用户自己的会话借助 Skill 与 CLI 查询状态、委派工作和处理授权，不替代项目 Main Agent。

项目保有长期会话

消息、任务与定时计划进入同一个 Conversation。进程可以重启；恢复依赖原生日志，而不只是一个 Thread ID。

Workspace 可以替换

原生工具在明确绑定的远端环境执行。工作卷保留文件；卷外依赖、进程、PTY 和内存不会随卷恢复。

持久化

共享本地存储，独立远端项目卷。

状态位置职责
Feynman 项目状态~/.feynman/rust-platform.sqlite3项目消息、Run、事件、任务、定时计划、授权、Thread ID 和 Workspace 绑定。
原生 Agent 会话~/.feynman/codex/原生 JSONL、状态库、配置和认证。项目 Agent 显式绑定此 Home，不沿用个人 harness 目录。
外部授权缓存~/.feynman/private/dws/Device 登录私有缓存；Connection 使用时重新验证，登录不等于业务获权。
外部权限模块状态~/.feynman/private/external-access/Connection、限期绑定、申请、最小审计及私有 Token 文件；不是加密 Vault。
远端项目文件独立 volume → /workspace代码、文件和卷内依赖；与本地 Home 分别备份。

Feynman 消息主存储仍是 SQLite。JSONL 导出尚未实现；复用 Codex 原生日志，不另外造上下文恢复机制。

已实现

Local-first 多项目，每项目一个 Main Agent

多项目管理、各自的长期会话、任务、显式审批、定时计划、用户目录、OpenSandbox 生命周期和原生 Executor。Schedule 默认暂停，依赖本机服务运行。

初版已实现

Agent、Schedule、环境与记忆

每项目至多一个未归档 Agent，可启停、归档、管理能力。Schedule / inbox send 使用持久 Inbox，来源独立历史可被 Agent 查询。详见 Agent 与 Schedule及环境、使用租约与记忆。多 Agent / Reviewer 后续；个人版不做强租户隔离。

这是个人可信 MVP：loopback 开发服务、Docker/runc 外层隔离、共享 bridge 与未认证执行端点。远端 :danger-full-access 仅在外层容器内且需运营者同意。不能直接对不可信租户开放。

DWS device 成功缓存可登记为 Connection，搜索使用指定绑定；GitLab、Git、Slate、Drlee 已有固定原生接入，支持受控 Sandbox clone。工具登录、业务 Grant 与执行审批是三个不同的权限环节。见 外部权限模块与实测边界。
